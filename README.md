# TANTRA

**Token-Adaptive Neural Transceiver for Resilient Audio** — a fully offline Android speech transceiver for low-bitrate links across Hindi, Gujarati, Marathi, Kannada, Malayalam, Tamil, Telugu, Odia, Bengali, and English.

TANTRA does not transmit audio. It performs local streaming speech recognition, commits only stable clauses, compresses the multilingual token stream, sends it through Wi-Fi LAN or Bluetooth, and synthesizes speech locally on the receiving phone. This turns a multi-kilobit voice channel into a text-rate channel while preserving an audio-first user experience.

> Engineering status: this repository contains the Android reference application, binary link protocol, ONNX model-pack contract, model training/export/evaluation pipeline, Modal GPU jobs, and automated tests. Neural weights are intentionally not committed. A competition APK is produced after exporting and signing the selected model packs; runtime inference remains fully offline.

## System path

```text
microphone
  -> AEC / NS / AGC
  -> SvaraGate adaptive VAD + endpointing
  -> Shruti streaming multilingual ASR
  -> StablePrefix clause committer
  -> AksharaLink token-delta packets
  -> Bluetooth RFCOMM or Wi-Fi TCP
  -> Vaani prefix-streaming TTS
  -> priority-aware local playback
```

### Why this is different

1. **Prefix-stable speech transport.** Partial ASR hypotheses are not spoken immediately. A clause is committed only after its prefix remains stable across consecutive hypotheses, avoiding audible corrections while starting TTS before the full utterance ends.
2. **Akshara token transport.** Indic grapheme clusters are mapped to a shared vocabulary and transmitted as compact varints. Indic Unicode commonly costs multiple UTF-8 bytes per code point; shared token IDs also carry punctuation and prosody.
3. **Link-adaptive reliability.** Unstable partials are best-effort, final clauses are acknowledged, and alerts use retry-until-ack semantics. The same application works over reliable Bluetooth RFCOMM or Wi-Fi TCP without changing the speech layer.
4. **One active model pack in memory.** A multilingual ASR core is shared while TTS packs can be activated per language. This keeps peak RAM bounded on low- and mid-range phones while all ten packs can remain stored offline.
5. **Alert-safe playback.** Alert frames pre-empt normal playback and request alarm audio focus. Android cannot ethically or technically guarantee an absolutely non-interruptible sound under every OEM policy; TANTRA implements the strongest user-authorized behavior and records whether the required permission is missing.

## Repository map

- `android/` — Kotlin/Jetpack Compose application, audio capture, ONNX inference contract, model-pack importer, Bluetooth/Wi-Fi transports, alert playback, and latency telemetry.
- `protocol/` — language-neutral AksharaLink specification plus Python reference codec and test vectors.
- `ml/` — raw-waveform multilingual CTC student, vocabulary builder, distillation hooks, TTS export contract, quantization, benchmarking, and Modal jobs.
- `docs/` — architecture, research decisions, model/data governance, deployment, security, and evaluation protocol.
- `benchmarks/` — machine-readable target budget and benchmark result schema.


## Android build

The Android project expects Android Studio/SDK 35 and JDK 17.

```bash
cd android
./gradlew testDebugUnitTest
./gradlew assembleDebug
```

On first launch, import a `.tantra-pack` file generated by the ML pipeline. A pack is copied into app-private storage and hash-verified. No model or audio leaves the device.

## Modal GPU pipeline

Configure a fresh token outside this repository, then run:

```bash
modal run ml/modal_app.py::gpu_smoke
modal run ml/modal_app.py::train_asr --config-name baseline
modal run ml/modal_app.py::export_asr --run-id <run-id>
modal run ml/modal_app.py::benchmark_pack --pack-path /artifacts/<pack>.tantra-pack
```

The checked-in Modal app uses persistent volumes for datasets/checkpoints and never embeds credentials. Dataset/model licenses must be accepted and recorded in `THIRD_PARTY_MODELS.md` before a competition build.

## Evaluation budgets

These are **targets**, not fabricated results. Every release stores measured values in `benchmarks/results/*.json`.

| Metric | Baseline target | Stretch target |
|---|---:|---:|
| Active ASR pack, int8 | <= 65 MB | <= 45 MB |
| Active TTS pack, int8 | <= 45 MB | <= 30 MB |
| App code/assets excluding packs | <= 35 MB | <= 25 MB |
| Peak RSS during duplex use | <= 420 MB | <= 300 MB |
| Idle listening CPU | <= 10% | <= 6% |
| Partial ASR update p95 | <= 500 ms | <= 300 ms |
| End-of-speech to final text p95 | <= 750 ms | <= 450 ms |
| Text arrival to first TTS audio p95 | <= 650 ms | <= 350 ms |
| Two-phone sentence-to-audio p95 | <= 1.8 s | <= 1.1 s |
| TTS real-time factor | < 0.55 | < 0.30 |

Accuracy targets are reported per language, dataset, device, and noise condition; no single aggregate WER is allowed to hide a weak language.

## Security and privacy

- Runtime is offline; the `INTERNET` Android permission is used only for local sockets.
- Model packs are SHA-256 verified.
- Session frames can be protected with a pre-shared 256-bit key and AES-GCM; Bluetooth pairing alone is not treated as application-layer authentication.
- Raw audio is ephemeral by default and is never persisted unless an explicit diagnostics setting is enabled.
- Secrets and Modal credentials are excluded by `.gitignore` and CI secret scanning.
